# Senin.me Mobile Release Configuration

Senin.me release automation is intentionally isolated from the upstream Discourse application accounts, signing repositories, bundle identifiers, package names, and credentials.

No Apple signing key, App Store Connect private key, Google Play service-account JSON, Android release keystore, password, Firebase configuration, or Match repository credential should be committed to this repository.

## Application identifiers

- iOS application: `me.senin.mobile`
- iOS Share Extension: `me.senin.mobile.ShareExtension`
- Android application: `me.senin.mobile`

The Xcode project and scheme are still internally named `Discourse` to minimize divergence from upstream. That internal project name is not an App Store identity.

## iOS environment

The following variables are required by the release lanes:

- `SENINME_IOS_TEAM_ID` — Apple Developer Team ID that owns the Senin.me identifiers.
- `SENINME_ASC_API_KEY_PATH` — local or CI path to a Senin.me App Store Connect API key JSON file.
- `SENINME_MATCH_GIT_URL` — private Senin.me Match certificate/profile repository.
- `SENINME_MATCH_GIT_BRANCH` — optional Match branch, defaults to `main`.
- `SENINME_MATCH_READONLY` — optional; defaults to `true`. Set to `false` only during an intentional signing-asset provisioning operation.
- `SENINME_APPLE_ID` — optional Apple account address used by Match when needed.

Run `fastlane ios certs` for App Store signing assets, `fastlane ios certs_adhoc` for ad-hoc assets, and `fastlane ios release` for a TestFlight build.

Remote push remains disabled until Senin.me-owned APNs/Firebase credentials and the Senin.me push relay are configured. Do not add the upstream Discourse push credentials.

## Android environment

Signed Android release lanes require:

- `SENINME_ANDROID_KEYSTORE_PATH` — path to the Senin.me release keystore. Prefer an absolute path in CI.
- `SENINME_ANDROID_KEY_ALIAS` — key alias in that keystore.
- `SENINME_ANDROID_STORE_PASSWORD` — keystore password.
- `SENINME_ANDROID_KEY_PASSWORD` — signing-key password.
- `SENINME_GOOGLE_PLAY_JSON_KEY` — path to the Senin.me Google Play service-account JSON file.
- `SENINME_PLAY_TRACK` — optional Google Play track; defaults to `internal`.

The Fastlane lanes pass signing values to Gradle at runtime. They never rewrite `android/gradle.properties`, copy a release keystore into the repository, or create `google-services.json`.

Run `fastlane android install` for a signed local release APK or `fastlane android release` for an Android App Bundle upload.

## Firebase and push

`android/app/google-services.json` is not generated by Fastlane. If Senin.me remote push is enabled in a later phase, use only the Firebase project owned by Senin.me and keep server-side FCM/APNs credentials outside the repository.

## Release validation

Before changing release automation, run the repository-owned checks rather than relying on editor formatting or a locally different tool version:

- `yarn eslint`
- `yarn prettier`
- `yarn test:unit`
- `ruby -c fastlane/Fastfile`
- `ruby -c fastlane/Matchfile`

The CI result for the exact pull-request head remains the release gate.

## Upstream isolation rule

Release automation must never reference or reuse:

- `discourse-org/discourse-mobile-keys`
- `team@discourse.org`
- the upstream Discourse Apple Team ID
- `org.discourse.DiscourseApp`
- Android package `com.discourse`

A Jest regression test and the Linting workflow protect these invariants and syntax-check the Fastlane Ruby files.
